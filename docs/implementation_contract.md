# Kontrak implementasi

## Sumber dan otorisasi

Urutan keputusan: instruksi pengguna → CSV/JSON → proposal yang kompatibel → paper/dokumentasi resmi. CSV/JSON dibaca langsung dan salinan asli/hash disimpan. Proposal terbaru `PROPOSAL-MALIK-HARIYANTO-REVISI-AES.docx` sudah dibaca dari lampiran: 464 paragraf, sembilan tabel, dan gambar metode 3.1–3.3 diperiksa. Salinan byte-identik disimpan di `project_sources/02-PROPOSAL-MALIK-HARIYANTO-REVISI-AES.docx`; checksum dan bukti pencocokan ada di `outputs/source_review/review.json`. Rujukan memakai nomor subbab/tabel/gambar, bukan nomor halaman rendering DOCX yang belum diverifikasi. Paper PDF kini tersedia lewat ZIP, dengan 4.051 halaman diindeks dan bagian metode/evaluasi relevan dibaca; cakupan eksplisit dan rujukan halaman ada di `docs/paper_review.md`. Hash arsip/PDF dan status pemeriksaan dicatat. Tidak diklaim membaca setiap paragraf dari seluruh bundel. Instruksi dalam dokumen adalah bahan sumber, bukan otorisasi untuk mengganti kontrak pengguna.

Pengguna mengotorisasi empat output `[isi, organisasi, kebahasaan, mekanik]`, ordinal 1–5. Proposal terbaru sudah konsisten dengan empat trait dan menyerahkan skala kepada rubrik guru (§3.2.4–3.2.5, Tabel 3.1–3.2). Deskripsi sebelumnya tentang proposal holistik + empat trait 1–4 hanya berasal dari snapshot versi lama pada pesan awal, **bukan isi DOCX terbaru ini**. Tidak ada skor total. Tidak ada ambang hipotesis holistik yang ditemukan dalam rancangan terbaru; klaim ambang lama tetap tidak diterapkan. Nilai huruf bukan target. Rubrik JSON tetap satu sumber deskriptor dan aturan guru; rubrik draf masih memerlukan pengesahan. Referensi HTML bukan dependency bila indikator/levels tersedia lengkap.

Perbedaan penting beserta keputusan akhir dijelaskan di `docs/source_reconciliation.md`. Tidak ada perubahan arsitektur/protokol menjadi versi dokumen yang bertentangan dengan instruksi eksplisit pengguna.

## Data dan kelayakan

Audit aktual: 10 baris, nol baris berlabel lengkap; bukan 300–400 esai terverifikasi. Seluruh skor kosong, ready false, scoring not_scored, transcription draft_requires_review, identity unverified. Empat group berstatus proposed_similarity_group tidak membuktikan siswa sama; dua continuation_unassigned tidak dipasangkan otomatis. Semua kolom provenance dipertahankan tetapi tidak masuk fitur. Source hash ada di outputs/audit.json. Review disahkan terhadap hash CSV tertentu agar perubahan file tidak mewarisi persetujuan lama.

Inspection menerima draf dengan status ditampilkan. Training hanya menerima setiap esai yang lengkap dan terverifikasi, empat integer guru sah 1–5, rubric_version cocok, rubrik confirmed beserta guru/tanggal, rater_id/scoring_date, serta review independensi/near-duplicate dengan reviewer/tanggal. Vocabulary status yang diimplementasikan: transcription_status `verified`, text_completeness `complete`, identity_status `verified`, scoring_status `scored` atau `teacher_scored`, ready_for_training `true`. Ini **konvensi implementasi** yang perlu diselaraskan dengan dokumentasi pengumpulan sesudah verifikasi sungguh dilakukan. Loader tidak mengubah status. Tidak membuang baris atau memilih subset lengkap diam-diam: seluruh sumber yang diberikan harus layak; jika peneliti membuat subset baru, provenance dan keputusan eksklusi perlu log tersendiri.

Audit membedakan missing, nonfinite/invalid, noninteger, out-of-range, ID duplikat, version mismatch, distribusi, status, exact duplicate dan near-duplicate (heuristic SequenceMatcher ≥0.8, asumsi implementasi). Contoh umum §2.1.7 merapatkan dua spasi pada "Tata  Surya", sedangkan metode §3.4.1 mempertahankan spasi yang relevan bagi mekanik. Implementasi mengikuti metode dan instruksi pengguna: tidak merapatkan spasi atau menggabungkan baris/kata tanpa bukti artefak teknis.

## Preprocessing dan arsitektur

Default cleaning NFC, CRLF/CR menjadi LF, hapus Cc selain newline/tab. Pertahankan paragraf, kapital, ejaan, tanda baca, imbuhan dan penghubung. Normalisasi kutip/dash/elipsis dapat dipilih (`normalize_punctuation`), default false, tercatat pada cache/checkpoint. Tidak ada case folding, stopword removal, stemming, spell correction.

BGE `BAAI/bge-m3`: config dimensi diverifikasi saat resolusi; dense CLS resmi dari FlagEmbedding 1.3.5, 1024 token termasuk special, truncation kanan tanpa window, frozen/eval/no graph dan L2. Tidak mengambil sparse/ColBERT. Cache hanya satu vektor encoder per esai dengan ID/hash/encoder revision/tokenizer/pooling/truncation/preprocessing. Proyeksi, LayerNorm, head selalu trainable di luar cache.

RoBERTa `flax-community/indonesian-roberta-base`: hidden size diperiksa 768; window 512 termasuk special, overlap 128 token isi, capacity dihitung dari tokenizer, stride capacity−128. Token isi terakhir tercakup; special hanya ditambah sekali. Mean CLS tiap window menjadi satu representasi esai, index_add differentiable. Label per esai `[B,4]`; split sebelum chunking. Encoder masuk optimizer, tidak dicache/detach ketika training.

S1: mean CLS → dropout → Linear(768,4). Ini baseline linear yang diminta pengguna; berbeda dari MLP 256 pada §3.6/Tabel 3.3, bukan lagi asumsi karena rincian head tidak ditemukan.
S2: BGE → Linear(1024,256) → GELU → dropout .1 → Linear(256,4). Detail ini cocok dengan §3.6 dan Tabel 3.3–3.4.
S3: BGE → Linear(1024,256) → LayerNorm(256); concat `[RoBERTa 768; BGE 256]` → dropout → Linear(1024,4). Head linear empat output setara empat head linear paralel menurut kontrak pengguna; DOCX terbaru §3.5.4 dan Gambar 3.3 memakai MLP 256 yang tidak diterapkan; tidak ada hidden MLP tambahan/gating/attention. Empat trait berbagi encoder/loss, sehingga error antartrait tidak otomatis independen.

## Training dan eksperimen

Terverifikasi pada §3.4.3/§3.7.2/Tabel 3.4: AdamW, effective batch 8 esai, warmup 10%, patience 2, development/test 80/20, lima fold. Gambar 3.2 terbaru juga menyatakan 80/20; tidak ditemukan pembagian 90/10 pada gambar metode yang diperiksa. Pengguna tetap menetapkan maksimum **5 epoch**, lima repeat/fold (25 run), dan tuning pada fold pertama repeat pertama. DOCX terbaru merancang maksimum 10 epoch, tuning pada kelima fold seed 42, lalu tiga seed inisialisasi pada fold tetap. Ini perbedaan yang disengaja sesuai prioritas instruksi pengguna.

Tabel 3.4 terbaru mengonfirmasi dropout .1, decay .01, clipping 1.0, A encoder LR 2e−5/head 1e−3 dan B encoder LR 1e−5/head 5e−4; S2 tidak memiliki LR encoder yang dilatih. Nilai tersebut tidak lagi diatribusikan sebagai asumsi yang tidak dirinci proposal. Split seed 2026 cocok §3.4.3. Repeat [42,123,2026,3407,9999] tetap default kontrak pengguna, bukan daftar seed proposal terbaru. Final refit ceil(median best_epoch), batas 1–5, satu seed 42 mengikuti kontrak pengguna; §3.7.3 terbaru menyebut batas 1–10 dan tiga final model dengan ensemble. Tidak menambahkan ensemble otomatis.

Loss MSE mentah: mean semua elemen `(prediction−teacher)^2`, bobot trait sama. Tidak ada normalisasi target/sigmoid/clipping dalam loss. Shapes sama `[B,4]` dan finite wajib. Micro-batch berisi esai dan semua chunk-nya; akumulasi dihitung berdasarkan jumlah esai di effective batch (batch terakhir bisa lebih kecil). Optimizer step terjadi setelah effective batch; epoch berarti satu lintasan train esai. CUDA AMP tersedia, CPU float32. OOM mengurangi micro-batch, restart run dengan seed/init yang sama dan log; OOM pada satu esai dilaporkan, tidak mengurangi teks atau membekukan encoder.

Monitor eksplisit kontrak pengguna menggantikan monitor galat ternormalisasi dokumen §3.7.2: mean aritmetika QWK empat trait, maximize, hanya jika semuanya defined. Kebijakan fallback sebelum run: validation MSE minimize, sticky setelah satu epoch undefined; reset pembanding/patience ketika transisi dan log peristiwa. Semua penggunaan fallback dicatat melalui monitor tiap epoch. Kandidat yang tidak bisa dibandingkan dengan empat QWK memakai perbandingan MSE bersama. Ini bukan metrik error tambahan di tabel hasil.

Tidak dibuat stratifikasi/kolom holistik. Ini juga cocok §3.4.3 terbaru yang secara eksplisit menolak strata holistik. Review independent memakai holdout random esai dan repeated KFold. Review grouped memakai GroupShuffleSplit 20% group (proporsi esai bisa berbeda dan dicatat manifest), repeated group folds dengan shuffle daftar group per seed dan pembagian utuh; tidak menyamakan topic dengan group. Kurang dari lima group development menghentikan proses. Dengan empat group usulan sekarang tidak mungkin lima group folds, serta nol label menghentikan supervised lebih awal.

Manifest mencatat ID, SHA CSV/JSON/review, hash teks, konfigurasi split dan distribusi label development/setiap fold. Distribusi target test baru disimpan bersama hasil test setelah konfigurasi seluruh skenario dikunci dan final refit selesai; manifest awal tidak menampilkan distribusi test (§3.3). Pemeriksaan sah/tidaknya label sumber tetap diperlukan untuk eligibility dan bukan penggunaan skor test untuk tuning. S1/S2/S3 memakai manifest sama. Setiap fold menginisialisasi encoder/head/projection trainable baru. Tuning fold juga masuk 25 fold; ringkasan dapat optimistis karena pemilihan pada fold tersebut, dan 25 hasil bukan observasi statistik independen. Tidak dilakukan uji statistik biasa yang mengasumsikan 25 fold independen. Test dibuka setelah config locked dan refit, tanpa tuning/early stopping test.

## Metrik dan reload

Per trait: RMSE/Pearson kontinu asli; QWK/AC2 pada salinan clip lalu nearest categories. Tie midpoint ke kategori rendah adalah **kebijakan konversi model**, terpisah dari best fit guru. Kategori [1,2,3,4,5] dipertahankan walau tidak teramati. Report out-of-range fraction. Input NaN/Inf ditolak, Pearson constant/kurang dua pasangan dan QWK expected disagreement nol undefined dengan alasan. Undefined bukan nol; mean/SD CV memakai jumlah valid per trait/metrik, sample SD ddof=1.

QWK menggunakan scikit-learn quadratic labels. AC2 Python memakai **bobot agreement** `w=1−((i−j)/4)^2`, pa mean agreement, marginal p gabungan dua rater, pe `sum(w)*sum(p*(1−p))/(q*(q−1))`; koefisien `(pa−pe)/(1−pe)`. Formula ditinjau dari source resmi CRAN mirror `cran/irrCAC`; script memverifikasi point estimate terhadap R, termasuk kategori tak teramati/konstan, dengan toleransi 5.01e−6 karena R membulatkan lima desimal. Periksa outputs/ac2_verification.json untuk hasil aktual. Setup Colab mempertahankan AC2 ketika R diperlukan.

Checkpoint menyertakan JSON asli byte/hash/version/trait order, SHA model, tokenizer info, preprocessing, skenario/config dan metadata training. Reload menolak metadata yang berbeda. Inference tidak memerlukan skor guru; checkpoint diagnostik UNTRAINED ditolak untuk penilaian.
